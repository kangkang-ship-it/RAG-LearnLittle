## 一、背景与目标

### 1.1 当前问题

1. **Token 膨胀**：同一用户在同一设备重复登录，每次都生成全新的 access_token + refresh_token 对，Redis 中累积大量有效 token，形成垃圾。
2. **不可见性**：用户无法知道自己在哪些设备上登录过，无法管理活跃会话。
3. **密码明文传输**：实际上这不是问题 —— HTTP body 中的密码在传输层由 TLS/HTTPS 加密，是行业标准做法。只需确保生产环境启用 HTTPS。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 会话复用 | 同一设备重复登录 → 旧 refresh token 立即失效，始终保持 1 个有效 token |
| 多设备独立 | 不同设备各自拥有独立会话，互不踢下线 |
| 会话可见 | 用户可查看所有活跃会话（设备名、IP、活跃时间） |
| 会话可控 | 用户可主动撤销任意设备的会话 |
| 向后兼容 | 不传 `device_id` 的老客户端保持现有行为 |
| 数量限制 | 每用户最多 5 个活跃会话，超出自动踢除最旧的 |

### 1.3 核心概念

```
一个"会话" = 一个 (user_id, device_id) 组合
```

- `device_id` 由**前端**生成（`crypto.randomUUID()`），存在 `localStorage` 中
- 同一个设备重复登录 → 复用同一个会话 → 旧 refresh token 被安全轮换 → Redis 中始终只有 1 个有效 token
- 不同设备登录 → 各自独立的会话 → 互不踢下线
- 用户可以查看/撤销任意设备的会话

## 二、关于"复用 Token"的澄清

方案要实现的是**会话级别的复用**，而不是字面复用同一个 JWT 字符串：

```
当前行为：
  登录 3 次 → Redis 里有 3 个有效的 refresh_token → 垃圾累积

方案 C 行为：
  登录 3 次 → 第 1 次的 token 被轮换失效 → Redis 里始终只有 1 个 → 干净
  前端视角：拿到了新 token（安全），后端视角：这是同一个会话（复用）
```

这是 **Refresh Token Rotation + Session Reuse** 的组合模式。

## 三、Redis 数据结构设计

在**不修改**现有 `refresh_token:{user_id}:{jti}` 白名单的基础上，**新增**两层映射：

```
┌─────────────────────────────────────────────────────────────────┐
│  新增 Key 1: session:{user_id}:{device_id}  (Hash)              │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  jti:          "abc123-def456"    ← 当前有效的 refresh jti│  │
│  │  device_name:  "Chrome / Windows" ← 用户可读的设备名      │  │
│  │  ip:           "192.168.1.100"    ← 最近一次登录 IP       │  │
│  │  user_agent:   "Mozilla/5.0..."   ← 原始 UA（仅记录）     │  │
│  │  created_at:   "2026-07-20T10:00" ← 会话创建时间          │  │
│  │  last_used:    "2026-07-20T14:30" ← 最后活跃时间          │  │
│  └───────────────────────────────────────────────────────────┘  │
│  TTL: 7 天（跟 refresh token 过期时间一致）                      │
├─────────────────────────────────────────────────────────────────┤
│  新增 Key 2: user_sessions:{user_id}  (Set)                     │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  {"device_001", "device_002", "device_003"}               │  │
│  └───────────────────────────────────────────────────────────┘  │
│  用途：快速列出用户所有活跃会话的 device_id                        │
│  TTL: 7 天（跟 refresh token 过期时间一致，每次活动刷新）         │
├─────────────────────────────────────────────────────────────────┤
│  保留 Key 3: refresh_token:{user_id}:{jti}  (String)            │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  "1"                                                      │  │
│  └───────────────────────────────────────────────────────────┘  │
│  用途：Refresh Token 白名单验证（现有逻辑不变）                   │
│  TTL: 7 天                                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 现有 Redis Key（不变）

| Key | 类型 | 用途 |
|-----|------|------|
| `login_attempts:{username}` | String | 登录失败计数器 |
| `token_blacklist:{jti}` | String | Access Token 黑名单 |
| `sse_token:{sse_jti}` | String | SSE 一次性 Token |
| `refresh_token:{user_id}:{jti}` | String | Refresh Token 白名单 |

```python
@router.post("/auth/login", summary="用户登录",
             dependencies=[Depends(rate_limit(endpoint_limit=5))])
async def login(data: UserLogin, request: Request,
                db: AsyncSession = Depends(get_db)):
    # --- 现有逻辑 ---
    await check_login_attempts(data.username)
    result = await db.execute(select(User).where(User.username == data.username))
    user = result.scalar_one_or_none()
    if not user or not verify_password(data.password, user.password):
        await record_login_failure(data.username)
        raise BusinessError(code=ErrorCode.PASSWORD_ERROR, http_status=401)
    await clear_login_attempts(data.username)

    # --- 新增：设备会话复用 ---
    if data.device_id:
        existing = await get_device_session(user.uuid, data.device_id)
        if existing:
            old_jti = existing.get("jti")
            if old_jti and await verify_refresh_token(user.uuid, old_jti):
                # 同一设备重复登录 → 撤销旧 token（rotation）
                await revoke_refresh_token(user.uuid, old_jti)

    # --- 生成新 token 对（现有逻辑）---
    access_token = create_access_token(user.uuid)
    refresh_token, jti = create_refresh_token(user.uuid)
    await store_refresh_token(user.uuid, jti)

    # --- 新增：存储/更新设备会话 ---
    if data.device_id:
        await store_device_session(
            user.uuid, data.device_id, jti,
            device_name=data.device_name,
            request=request,
        )
        await enforce_session_limit(user.uuid, max_sessions=5)

    return success_response(data=TokenResponse(
        access_token=access_token,
        refresh_token=refresh_token,
        token_type="bearer",
        expires_in=ACCESS_TOKEN_EXPIRE_MINUTES * 60,
        device_id=data.device_id,  # 回传给前端
    ).model_dump())
```

### 5.5 Device Name 解析

不引入额外依赖，使用正则从 User-Agent 中提取设备和浏览器信息：

```python
import re

def parse_device_name(user_agent: str) -> str:
    """
    从 User-Agent 解析可读设备名

    优先级：前端提供的 device_name > 服务端 UA 解析 > "Unknown Device"

    示例：
        "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0"
        → "Chrome / Windows"
    """
    if not user_agent:
        return "Unknown Device"

    # 操作系统检测
    os_name = "Unknown"
    if "Windows" in user_agent:
        os_name = "Windows"
    elif "Mac OS" in user_agent:
        os_name = "macOS"
    elif "iPhone" in user_agent or "iPad" in user_agent:
        os_name = "iOS"
    elif "Android" in user_agent:
        os_name = "Android"
    elif "Linux" in user_agent:
        os_name = "Linux"

    # 浏览器检测
    browser = "Unknown"
    if "Edg" in user_agent:
        browser = "Edge"
    elif "Chrome" in user_agent and "Safari" in user_agent:
        browser = "Chrome"
    elif "Safari" in user_agent:
        browser = "Safari"
    elif "Firefox" in user_agent:
        browser = "Firefox"

    return f"{browser} / {os_name}"
```

## 六、前端配合清单

### 6.1 Device ID 管理

```javascript
/**
 * 获取或生成设备唯一标识
 * 存储在 localStorage 中，浏览器清数据后会丢失（此时视为新设备）
 */
function getDeviceId() {
  let deviceId = localStorage.getItem('device_id');
  if (!deviceId) {
    deviceId = crypto.randomUUID();
    localStorage.setItem('device_id', deviceId);
  }
  return deviceId;
}

/**
 * 获取设备可读名称（可选）
 */
function getDeviceName() {
  const ua = navigator.userAgent;
  // 简单的客户端解析，也可以直接传空让服务端解析
  return getBrowserName() + ' / ' + getOSName();
}
```

### 6.2 登录时携带 device_id

```javascript
async function login(username, password) {
  const deviceId = getDeviceId();
  const resp = await fetch('/api/v1/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      username,
      password,
      device_id: deviceId,
      device_name: getDeviceName(),  // 可选
    }),
  });

  const data = await resp.json();

  // 回传的 device_id 可能与本地一致，但仍以服务端回传为准存储
  if (data.data?.device_id) {
    localStorage.setItem('device_id', data.data.device_id);
  }

  return data;
}
```

| 场景 | 当前行为 | 方案 C 行为 |
|------|---------|------------|
| 同一设备重复登录 | 产生 N 个有效 token | 旧 token 立即失效，始终保持 1 个 |
| 不同设备登录 | 各自独立 token | 各自独立会话，互不影响 |
| 密码泄露后被攻击者登录 | 产生新 token，受害者不知情 | 产生新会话，受害者可在会话列表中发现异常 |
| 踢掉特定设备 | 只能全踢（改密码） | 精确撤销某个设备会话 |
| 设备数量限制 | 无限制 | 最多 5 个活跃设备，超出自动踢最旧的 |
| 老客户端（不传 device_id） | 正常工作 | 正常工作（向后兼容） |
| XSS 窃取 device_id | - | device_id 单独无效，必须配合有效 token |
| Token Rotation 防重放 | 已有 | 保持不变，安全性不降低 |

## 十、潜在问题与应对

| 问题 | 应对方案 |
|------|---------|
| 用户清除浏览器数据后 `device_id` 丢失 | 视为新设备，创建新会话；旧会话在 TTL 过期后自动清理 |
| 同一浏览器多个 Profile | 每个 Profile 有独立 localStorage，各自生成独立 device_id，符合预期 |
| 用户使用隐私模式 | 每次都是新 device_id，会产生大量废弃会话，但 TTL 到期自动清理 |
| `device_id` 可以被用户手动修改 | 不影响安全性，修改后视为新设备 |
| IP 变化（移动网络、VPN） | `last_used` 和 `ip` 只是元数据，不影响 token 验证逻辑 |
| 会话列表为空（老用户升级） | 返回空列表 `[]`，符合预期 |
