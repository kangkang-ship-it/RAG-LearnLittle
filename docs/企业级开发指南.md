## 1. Agent 运行方式

### 核心机制：ReAct 循环

主体是 **ReAct 循环**，不是预编排的固定 workflow：

```
LLM 决定调工具 → 执行 → 结果回喂 → 再推理 → 循环直到出答案或触顶 maxTurns
```

### Plan-and-Executor 融合

| 任务类型 | 运行模式 |
|---------|---------|
| 简单问答 | 直接 ReAct |
| 复杂任务（≥3步） | 调用 `task_create` 建显式计划（goal + steps + doneCriteria），按 `in_progress → completed` 严格推进 |

> 仅对复杂任务启用 Plan-and-Executor，属于按需融合而非全量替代。

### Reflection（反思机制）

工程化的**弱形式** Reflection，不是 Reflexion 那种"写反思日记重跑"：

- **重复错误检测**：同一错误出现 ≥2 次，working memory 标记 `[RED HERRING]` / 循环警告，强制换方向（实测：`file_read` 连续 4 次相同结果 → 避免重复试错）
- **任务完成自检**：强制三维度自检（数据 / 逻辑 / 结果）
- **回测程序化验证**：读 `trades.csv` 查 T+1 制度违规、卖空、异常收益

## 2. 向量数据库与知识切片

### 技术选型

**没有使用专门向量库**（无 Chroma / Milvus / PGVector）。

| 组件 | 实现方式 |
|------|---------|
| 存储 | 本地 JSON |
| 向量计算 | 云端 embedding API（可配 OpenAI `text-embedding-3-small` 或智谱 `embedding-3`） |
| 检索 | 内存余弦相似度 |

> 定位是"跨会话经验库"（几十~几百条），这个规模暴力检索够用。

### 切片维度

- **单位**：一条经验（`knowledge_add` 写入的自包含文本，≤500字）
- **分类**：`research` / `strategy` / `pitfall` / `code_snippet` / `fact`
- **无文档级 chunk 切块**：因为它不是文档问答库

> ⚠️ **实测**：当前本机 `config.json` 里 embedding 未配置（off），知识库 RAG 处于关闭状态。

## 3. 记忆模块设计

### 三层 Markdown 文件式记忆

**不是向量库**，纯文本直接注入 system prompt。

| 层级 | 文件 | 当前大小 | 用途 |
|------|------|---------|------|
| 长期 | `long_term.md` | 7.5 KB | 跨项目事实 / 规则 / 踩坑根因 |
| 近期 | `recent.md` | 5 KB | 最近任务摘要 |
| 临时 | `temp.md` | 0 KB | 会话内中间状态 |

### 存储格式

```
YYYY-MM-DD [类型] 内容
```

### 容量控制

- 三个字节上限：`maxLongTermMemoryBytes` 等
- 压缩阈值：`compressThresholdTokens`
- 另有 session 文件（本机 7 个）存完整会话，plan 状态可跨会话恢复

### 设计优势

- **零延迟、零依赖**："提示词注入式记忆"
- **代价**：容量小

## 4. Prompt 工程设计

高度结构化的工程 prompt（`soul.md`，几万字），**静态规范 + 动态事实分离**。

### 分层结构

| 层级 | 内容 | 目的 |
|------|------|------|
| **身份层** | 角色（量化投研顾问）、权限边界 | 行为约束 |
| **环境铁律层** | 路径表、"用户说 X → 做 Y"映射 | 防 LLM 凭记忆猜路径 |
| **领域知识层** | A 股硬约束（T+1 制度、涨跌停 ±10/20/30%）、风控/仓位表 | 领域准确性 |
| **工作流层** | 投研 8 步流程、Plan 模式节奏、执行铁律 | 流程规范 |
| **防错层**（特色） | 反模式清单：工具选择决策表、已知引擎缺陷声明、token 截断阈值表、超时铁律 | 防御性编程 |
| **动态注入层** | 运行时路径、实测可用的 Python 库清单、数据库 manifest、工具目录、记忆 | 避免 prompt 信息过期 |
| **领域宪法** | 量化任务 15 条质量原则（数据 / 复权 / 回测 / 偏差控制 / 可复现性） | 质量保障 |

### 设计哲学

> **能硬编码的规则全硬编码，不依赖模型自觉。**

## 5. RAG 与 Tools 机制

### Tools（函数调用）

- 注册 **30+ 个工具**，标准 function calling
- **Schema 分层**：
  - 核心工具 → 直接注入
  - 其余工具 → `tool_schema` 按精确名按需查，避免一次灌爆 token
- **安全纪律**：
  - 写入必须走串行化队列（`db_execute`）
  - 破坏性操作必须用户授权

### RAG（检索增强生成）

- **触发点固定**：
  - 新研究任务开始前 → 强制 `knowledge_search`
  - 结束后满足条件 → 强制 `knowledge_add`
- **策略**：任务级 RAG，不是每轮都检索（且当前默认关闭）
- **Skill 系统**：11 份 SOP 文档，按需 `skill_read` 批量读 → 本质是手动触发的文档注入式 RAG
- **金融数据**：不走向量检索，走 SQL（本地 DuckDB 优先 → 云端 ClickHouse 镜像）

## 6. Agent 运行流程

```
用户消息
   ↓
组装 prompt（静态 soul.md + 动态注入：路径 / 环境 / 记忆 / 工具目录 / 会话历史）
   ↓
判复杂度 → 简单：直接 ReAct ｜ 复杂：task_create 建计划
   ↓
ReAct 循环（≤ maxTurns 轮）：LLM → tool_call → 沙箱执行 → 结果回喂
   ↳ 错误 ≥2 次 → working memory 警告强制换方向
   ↳ 上下文超阈值 → 压缩历史
   ↓
结果验证（回测三段验证 / 质量三维复核）
   ↓
记忆落盘（long_term / recent / temp）+ 可选 skill 沉淀
   ↓
SSE 流式输出（POST /api/agent/stream，done 事件带全量备份文本兜底）
```

## 7. 未来演进方向

从架构现状推断：

| 方向 | 说明 |
|------|------|
| **知识库 RAG 默认开启** | embedding 配置已预留 |
| **多 Agent 化** | 定位本就是"一人替代研究员 / 风控 / 交易员 / 基金经理"，天然适合拆角色协作 |
| **自主巡航** | `schedule_task` 已支持 interval / sequential 任务链，是自动盯盘 / 自动执行的地基 |
| **策略实盘自动化** | `strategyExecutor` 4 个定时任务（数据检查 → 信号 → 开盘/收盘执行）已就位 |

## 9. 服务端架构

后端 **Fastify** 起在 `localhost:3001`，可独立部署在服务器；前端 Electron（或浏览器）通过 HTTP + SSE 访问。

```
Electron 桌面壳（React + Widget 系统）
      ↕ HTTP localhost:3001 + SSE 流式
Fastify 后端（Agent 调度 / SQL / Widget 构建）
      ↕
Python 3.13 便携运行时（量化计算）
DuckDB 本地库 + ClickHouse 云端行情镜像
QMT WebSocket 代理（可选，实盘）
```

## 10. 项目分层架构

| 层 | 组成 |
|----|------|
| **表现层** | Electron + React，Widget 系统（唯一 UI 形式，桌面窗口管理） |
| **Agent 层** | iwagent（soul.md 提示词 + 30+ 工具 + 三层记忆 + skill SOP + 会话管理） |
| **服务层** | Fastify API：`/api/agent/stream`、`/api/sql`、`/api/strategies`、`/api/qmt-proxy`、`/api/widget-plugins`、`/api/themes` |
| **计算层** | Python 3.13 便携版 + iwa_strategy SDK + iwa_data 数据模块 |
| **数据层** | 本地 DuckDB（主库）+ 依瓦云 ClickHouse（A 股行情镜像）+ 公开行情 API 兜底 |
| **实盘层** | MiniQMT / xtquant → `qmtwss.py` WebSocket 代理（`ws://127.0.0.1:8765`） |

## 12. 模型微调策略

### 零微调

**没有微调。** 项目里看不到任何微调产物：

- 无 LoRA 权重
- 无训练数据
- 无训练管线

### 设计选择

> 全部能力靠 **prompt 工程 + 工具链 + 记忆系统** 实现。

| 维度 | Prompt 硬编码 | 微调 |
|------|-------------|------|
| 可维护性 | ✅ 改 markdown 即可 | ❌ 需重训模型 |
| 可审计性 | ✅ 规则明文可见 | ❌ 权重黑盒 |
| 热更新 | ✅ 改规则即时生效 | ❌ 需重新部署 |
| 量化领域规则 | ✅ 适合 | ❌ 过度复杂 |

## 13. 工具链概览

**30+ 个工具**，标准 function calling 循环，分七大类：

| 类别 | 工具示例 | 用途 |
|------|---------|------|
| **文件原子操作** | `file_read` / `file_write` / `file_patch` | 文件读写 |
| **代码导航** | `grep` / `lookup_symbol` | 代码搜索 |
| **沙箱执行** | `python` / `node` / `shell` | 安全代码执行 |
| **数据库** | `db_query` / `db_execute` / `iwaos_query` | 数据查询与写入 |
| **回测** | `backtest_strategy`（异步） | 策略回测 |
| **Widget 生命周期** | `build` / `emit_ui_command` / `inspect` | UI 组件管理 |
| **记忆与任务** | `memory_update` / `task_create` / `schedule_task` | 状态管理与调度 |
