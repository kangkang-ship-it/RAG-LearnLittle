## 一、问题分析

### 1.1 当前现状

根据 [agent_context_memory_architecture.md](./agent_context_memory_architecture.md) 第十节，当前设计存在以下缺口：

| 缺失能力 | 风险 |
|---------|------|
| 无 Token 预算管理 | 对话过长时超出模型上下文窗口，请求失败 |
| 无滑动窗口截断 | 全量加载所有历史消息，prompt token 线性增长 |
| 无摘要压缩 | 旧对话信息只能被截断丢弃，无法保留关键上下文 |
| 无长对话降级策略 | 没有优雅的降级路径，一旦超限就是硬错误 |

### 1.2 根因

```
MySQL chat_messages 全量加载
        │
        ▼
遍历全部消息 → 列表膨胀
        │
        ▼
PromptTemplate 注入 → 超出模型上下文窗口 → 请求失败
```

三个模块的分工：

- **Token 预算管理器**：回答"还能塞多少"——感知模型能力上限，动态分配配额
- **滑动窗口**：回答"哪些要保留原文"——最近 N 轮完整保留，超出部分不进入 prompt
- **里程碑摘要**：回答"旧的怎么压缩"——超窗口部分增量合并为摘要，关键信息不丢失

## 三、模块一：Token 预算管理器

### 3.1 职责

精确控制每次 LLM 调用中各组件消耗的 token 数量，确保总消耗不超出模型的上下文窗口限制。

### 3.2 预算模型

```
模型上下文窗口 (以 Qwen 32K 为例 = 32768 tokens)
│
├── system_prompt      :  ~500 tokens  (固定，main_prompt.txt 长度)
├── rag_context        : ~2000 tokens  (上限，超出截断)
├── conversation_summary: ~800 tokens  (上限，摘要文本)
├── chat_history       : ~4000 tokens  (动态配额，核心控制对象)
├── current_input      :  ~300 tokens  (估算，单条用户消息)
├── agent_scratchpad   : ~4000 tokens  (预留，工具调用往返)
└── safety_margin      : ~1000 tokens  (安全余量)
                         ─────────
                          12600 tokens  (实际消耗远小于窗口上限)
```

### 3.3 核心数据结构

```python
# 文件位置: app/services/token_budget.py

from dataclasses import dataclass, field
from typing import Optional

@dataclass
class TokenBudget:
    """Token 预算分配"""
    model_context_size: int = 32768        # 模型上下文窗口总大小

    # 固定分配
    system_prompt: int = 500              # 系统提示词
    rag_context_max: int = 2000           # RAG 上下文上限
    summary_max: int = 800               # 摘要文本上限
    agent_scratchpad_reserve: int = 4000  # 工具调用预留
    current_input_estimate: int = 300     # 当前输入估算
    safety_margin: int = 1000             # 安全余量

    @property
    def fixed_budget(self) -> int:
        """固定消耗的 token 总量"""
        return (
            self.system_prompt
            + self.rag_context_max
            + self.summary_max
            + self.agent_scratchpad_reserve
            + self.current_input_estimate
            + self.safety_margin
        )

    @property
    def available_for_history(self) -> int:
        """chat_history 可用的 token 配额"""
        return max(0, self.model_context_size - self.fixed_budget)
```

### 3.4 Token 计数

```python
import tiktoken

class TokenCounter:
    """Token 计数器（基于 tiktoken）"""

    # 编码器缓存（避免重复加载）
    _encoders: dict[str, tiktoken.Encoding] = {}

    @classmethod
    def get_encoder(cls, model_name: str = "gpt-4") -> tiktoken.Encoding:
        """获取编码器（带缓存）"""
        if model_name not in cls._encoders:
            try:
                cls._encoders[model_name] = tiktoken.encoding_for_model(model_name)
            except KeyError:
                # 回退到 cl100k_base（GPT-4 / GPT-3.5 通用编码）
                cls._encoders[model_name] = tiktoken.get_encoding("cl100k_base")
        return cls._encoders[model_name]

    @classmethod
    def count(cls, text: str, model_name: str = "gpt-4") -> int:
        """计算文本的 token 数量"""
        encoder = cls.get_encoder(model_name)
        return len(encoder.encode(text))

    @classmethod
    def count_messages(cls, messages: list, model_name: str = "gpt-4") -> int:
        """计算消息列表的总 token 数（含角色标记开销）"""
        encoder = cls.get_encoder(model_name)
        total = 0
        for msg in messages:
            # 每条消息有固定开销：角色标记 ~4 tokens
            total += 4
            content = msg.get("content", "") if isinstance(msg, dict) else str(msg)
            total += len(encoder.encode(content))
        total += 2  # 序列结束标记
        return total
```

### 3.5 动态配额分配流程

```
TokenBudgetManager.allocate(rag_context_len: int) → history_quota: int

1. 计算 fixed_budget
2. 实际 rag 消耗 = min(rag_context_len, rag_context_max)
3. quota = model_context_size - fixed_budget - 实际 rag 消耗
4. 确保 quota >= MIN_HISTORY_TOKENS (最小保证，如 500)
5. 返回 quota
```

## 四、模块二：滑动窗口截断

### 4.1 职责

在 token 预算约束下，从最新的消息开始向前选取，直到配额用尽。超出窗口的消息不出现在 prompt 中。

### 4.2 核心逻辑

```python
# 文件位置: app/services/memory_compressor.py

from typing import List, Tuple
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage, BaseMessage


class MemoryCompressor:
    """
    对话记忆压缩器

    在 token 预算约束下，对全量历史执行：
    1. 滑动窗口截断：保留最近 N 轮原文
    2. 摘要拼接：将已有摘要注入为 SystemMessage
    """

    def __init__(self, budget: TokenBudget, token_counter: TokenCounter):
        self.budget = budget
        self.counter = token_counter

    def build_context(
        self,
        all_messages: list[dict],      # 全量消息 [{"role": "user/assistant", "content": "..."}]
        existing_summary: str = "",     # 已有的里程碑摘要
        model_name: str = "gpt-4",
    ) -> Tuple[List[BaseMessage], int]:
        """
        构建压缩后的消息上下文

        策略：
        1. 先计算摘要占用的 token
        2. 从最新消息向前遍历，逐条累计 token
        3. 超出配额时停止

        Returns:
            (消息列表, 已用 token 数)
        """
        quota = self.budget.available_for_history
        messages: list[BaseMessage] = []
        used_tokens = 0

        # Step 1: 注入已有摘要（如果有）
        if existing_summary:
            summary_text = self._truncate_summary(existing_summary, model_name)
            summary_tokens = self.counter.count(summary_text, model_name)
            if summary_tokens <= self.budget.summary_max:
                messages.append(SystemMessage(
                    content=f"[历史对话摘要]\n{summary_text}"
                ))
                used_tokens += summary_tokens
                quota -= summary_tokens

        # Step 2: 滑动窗口填充（从最新向最旧）
        window_messages: list[BaseMessage] = []
        window_tokens = 0

        # 反转消息列表，从最新开始处理
        for msg in reversed(all_messages):
            # 估算本条消息的 token 数
            msg_tokens = self.counter.count(msg["content"], model_name)

            # 检查是否超出配额
            if window_tokens + msg_tokens > quota:
                break

            # 成对添加（保证 user + assistant 完整性）
            if msg["role"] == "user":
                window_messages.append(HumanMessage(content=msg["content"]))
            elif msg["role"] == "assistant":
                window_messages.append(AIMessage(content=msg["content"]))

            window_tokens += msg_tokens

        # 反转回正序（时间升序）
        window_messages.reverse()
        messages.extend(window_messages)
        used_tokens += window_tokens

        return messages, used_tokens

    def _truncate_summary(self, summary: str, model_name: str) -> str:
        """确保摘要文本不超出 token 上限"""
        encoder = self.counter.get_encoder(model_name)
        tokens = encoder.encode(summary)

        if len(tokens) <= self.budget.summary_max:
            return summary

        # 截断到上限（保留完整性，在句号后截断）
        truncated = encoder.decode(tokens[:self.budget.summary_max])
        last_period = max(truncated.rfind("。"), truncated.rfind("."), truncated.rfind("\n"))
        if last_period > len(truncated) // 2:
            truncated = truncated[:last_period + 1]
        return truncated
```

## 五、模块三：里程碑摘要压缩

### 5.1 职责

当对话轮数达到阈值时，将超出窗口的旧消息压缩为一段结构化摘要，持久化存储，避免信息完全丢失。

### 5.2 触发策略

```
触发条件:
┌────────────────────────────────────────────────┐
│  条件1: 消息总数 > SUMMARIZE_THRESHOLD (默认40条=20轮)│
│  条件2: 距上次摘要生成 > MIN_SUMMARY_INTERVAL (默认10轮)│
│  条件3: 摘要未冻结（用户可手动冻结，停止自动更新）  │
└────────────────────────────────────────────────┘

触发时机: after_agent 中间件钩子中异步执行（不阻塞响应）
```

### 5.3 增量摘要算法

```
增量摘要: 新摘要 = 融合(旧摘要, 新被压缩的消息块)
```

```
第一次触发 (消息数达到40):
┌──────────────────────────────────────────────┐
│  消息#1~#20  →  LLM 生成摘要 v1              │
│               "用户讨论了Python异步编程，     │
│                决定使用asyncio+FastAPI..."    │
│              存入 chat_summaries              │
│              last_summarized_msg_id = 20      │
└──────────────────────────────────────────────┘

第二次触发 (消息数达到60):
┌──────────────────────────────────────────────┐
│  已有摘要 v1                                  │
│  消息#21~#40  →  LLM 融合生成摘要 v2          │
│               "用户讨论了Python异步编程，     │
│                决定使用asyncio+FastAPI...     │
│                后续讨论了数据库选型，选择     │
│                MySQL+Redis组合..."            │
│              更新 chat_summaries              │
│              last_summarized_msg_id = 40      │
└──────────────────────────────────────────────┘
```

### 5.4 摘要生成 Prompt

```python
SUMMARY_PROMPT = """你是一个对话摘要助手。请阅读以下信息，生成一段简洁的结构化摘要。

## 已有的历史摘要
{existing_summary}

## 新增的对话片段（需要融合到摘要中）
{new_messages}

## 要求
1. 融合已有摘要和新对话，生成新的完整摘要
2. 重点保留以下类型的信息：
   - **关键决策**：用户做了什么技术/业务决策
   - **用户偏好**：用户表达过的喜好、习惯、要求
   - **未完成任务**：对话中提到但尚未完成的事项
   - **重要事实**：用户提供的关键信息
   - **上下文延续**：可能需要跨轮次引用的信息
3. 摘要长度控制在 500 字以内
4. 使用中文
5. 仅输出摘要文本，不要加任何前缀或解释"""
```

### 5.5 核心实现

```python
# 文件位置: app/services/memory_compressor.py (续)

async def generate_incremental_summary(
    chat_model,                     # LLM 模型实例
    session_id: str,                # 会话 ID
    existing_summary: str,          # 已有的摘要文本
    new_messages: list[dict],       # 新被压缩的消息块
    last_msg_id: int,              # 新摘要覆盖到的最后一条消息 ID
    db: AsyncSession,              # 数据库会话
) -> str:
    """
    生成增量摘要并持久化

    流程：
    1. 用 LLM 融合已有摘要 + 新消息块
    2. 写入 / 更新 chat_summaries 表
    3. 返回新摘要文本
    """
    # 格式化新消息
    formatted = []
    for msg in new_messages:
        role_label = "用户" if msg["role"] == "user" else "助手"
        formatted.append(f"[{role_label}]: {msg['content'][:300]}")  # 每条截断到300字

    # 构建 prompt
    prompt = SUMMARY_PROMPT.format(
        existing_summary=existing_summary or "（暂无历史摘要）",
        new_messages="\n\n".join(formatted),
    )

    # 调用 LLM 生成摘要
    from langchain_core.messages import HumanMessage
    response = await chat_model.ainvoke([HumanMessage(content=prompt)])
    new_summary = response.content.strip()

    # 持久化到数据库
    await DatabaseSessionManager.update_summary(
        db, session_id, new_summary, last_msg_id
    )

    return new_summary
```

### 5.6 摘要与窗口的协作

```
请求时消息组装流程:

1. 查询 chat_summaries 表 → 获取 existing_summary
2. 查询 chat_messages 表 → 获取全量消息
3. 滑动窗口截断（基于 token 配额）
4. 组装:
   [SystemMessage: system_prompt]            ← 系统提示词
   [SystemMessage: "历史对话摘要: ..."]      ← 摘要（如果有）
   [HumanMessage/AIMessage: 窗口内消息...]   ← 滑动窗口内容

关键：摘要和窗口之间没有重叠 —— 摘要覆盖的部分不在窗口中
```

class ChatSummary(Base):
    """
    聊天摘要模型

    每个会话保持一条摘要记录，采用增量更新策略。
    last_message_id 记录摘要覆盖到的消息位置，
    下次摘要时仅需处理该 ID 之后的新消息。
    """
    __tablename__ = "chat_summaries"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    session_id: Mapped[str] = mapped_column(
        String(36), ForeignKey("chat_sessions.id", ondelete="CASCADE"),
        nullable=False, unique=True
    )
    summary_text: Mapped[str] = mapped_column(Text, nullable=False)
    last_message_id: Mapped[int] = mapped_column(Integer, nullable=False)
    version: Mapped[int] = mapped_column(Integer, nullable=False, default=1)
    token_count: Mapped[int | None] = mapped_column(Integer, nullable=True, default=0)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(
        DateTime, server_default=func.now(), onupdate=func.now()
    )

    session = relationship("ChatSession", back_populates="summary")

    """

### 7.4 摘要检查逻辑

```python
# memory_compressor.py

async def check_and_summarize(
    db: AsyncSession,
    chat_model,
    session_id: str,
    threshold: int = 40,
) -> None:
    """
    检查是否需要生成摘要，如需要则异步执行

    判断条件：
    1. 消息总数 > threshold
    2. 距上次摘要后新增消息数 > MIN_SUMMARY_INTERVAL
    3. 摘要未被冻结
    """
    # 检查会话 metadata 中的摘要冻结标志
    session = await db.get(ChatSession, session_id)
    if not session:
        return

    meta = session.metadata_ or {}
    if meta.get("summary_frozen"):
        return

    # 获取消息总数
    from sqlalchemy import func
    result = await db.execute(
        select(func.count(ChatMessage.id)).where(ChatMessage.session_id == session_id)
    )
    msg_count = result.scalar()

    if msg_count < threshold:
        return

    # 获取上次摘要覆盖位置
    summary_result = await db.execute(
        select(ChatSummary).where(ChatSummary.session_id == session_id)
    )
    existing = summary_result.scalar_one_or_none()
    last_summarized_id = existing.last_message_id if existing else 0

    # 检查是否有足够的新消息值得重新摘要
    new_msg_count = msg_count - last_summarized_id
    if new_msg_count < MIN_SUMMARY_INTERVAL:
        return

    # 加载需要被压缩的消息（last_summarized_id 之后的消息，但不包括最近窗口内的）
    # 压缩范围：[last_summarized_id, 最新消息 - KEEP_RECENT_ROUNDS]
    from sqlalchemy import and_
    keep_recent = 20  # 保留最近 20 条不压缩

    compress_result = await db.execute(
        select(ChatMessage)
        .where(
            and_(
                ChatMessage.session_id == session_id,
                ChatMessage.id > last_summarized_id,
            )
        )
        .order_by(ChatMessage.id.asc())
    )
    compress_messages = compress_result.scalars().all()

    # 保留最近的消息不压缩
    if len(compress_messages) <= keep_recent:
        return
    compress_messages = compress_messages[:-keep_recent]

    # 格式化消息
    new_msgs = [
        {"role": m.role, "content": m.content}
        for m in compress_messages
    ]

    # 生成增量摘要
    existing_text = existing.summary_text if existing else ""
    await generate_incremental_summary(
        chat_model=chat_model,
        session_id=session_id,
        existing_summary=existing_text,
        new_messages=new_msgs,
        last_msg_id=compress_messages[-1].id,
        db=db,
    )

    logger.info(
        f"摘要更新完成: session_id={session_id}, "
        f"压缩消息数={len(compress_messages)}, "
        f"截止消息ID={compress_messages[-1].id}"
    )
```

## 九、边缘场景处理

### 9.1 摘要生成失败

```
场景: LLM 调用摘要 prompt 时超时或报错

处理:
1. 捕获异常，记录 warning 日志
2. 保留旧摘要不变
3. 不阻塞主流程（after_agent 异步钩子中执行）
4. 连续失败 3 次 → 冻结摘要生成 → 仅依赖滑动窗口
```

### 9.2 Token 预算极端不足

```
场景: 模型上下文窗口很小（如 4096），固定消耗已经占满

处理:
1. MIN_HISTORY_TOKENS 保证至少 500 tokens 给历史
2. 如果连 500 都没有 → 不注入任何历史，仅当前消息
3. 日志 warning 级别记录降级事件
```

### 9.3 摘要冻结点

```
场景: 用户手动冻结摘要（通过 API 或设置）

处理:
1. 设置 chat_sessions.metadata_.summary_frozen = True
2. 摘要不再自动更新
3. 滑动窗口继续正常工作
4. 已有的摘要仍会注入 prompt（除非用户手动清除）
```

### 9.4 会话迁移 / 模型切换

```
场景: 用户更换模型（从 8K 模型切换到 128K 模型）

处理:
1. TokenBudget 初始化时读取新的 CONTEXT_SIZE
2. 窗口自动扩大，更多历史进入窗口
3. 摘要无需重新生成
4. 建议在 chat_sessions.metadata 中记录上次使用的模型
```

### 9.5 只有一条消息的会话

```
场景: 新会话，仅有当前消息

处理:
1. msg_count = 1，不触发摘要
2. 滑动窗口仅包含当前消息（或为空）
3. Token 预算完全充裕
4. 正常流程，无任何压缩开销
```

## 十一、潜在改进方向

1. **Token 预算感知**：在注入 `chat_history` 前估算 token 数，超出阈值时做滑动窗口截断或摘要压缩
2. **记忆压缩**：利用中间件钩子（`after_agent`），对长对话自动生成阶段性摘要，将旧轮次替换为压缩后的摘要消息
3. **Redis 缓存热历史**：最近 N 轮对话缓存到 Redis，减少 MySQL 查询
4. **重要记忆提取**：从对话中提取关键事实存入独立的"长期记忆"存储
5. **RAG 上下文与对话历史的协同**：当前 RAG 结果和对话历史是独立的，可考虑让 RAG 检索 query 时融入最近的对话上下文
